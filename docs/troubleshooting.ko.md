# 문제 해결

[README](../README.ko.md) | [English](troubleshooting.md) | **한국어**

## 공통 문제 해결

먼저 [공통 Bluetooth 문제 해결](https://github.com/eigger/blesession/blob/main/docs/troubleshooting.ko.md)을 확인하세요. 프록시 펌웨어·보드 리비전·연결 슬롯·거리·네트워크 확인과 Home Assistant 등록은 [Bluetooth proxy 안내](https://github.com/eigger/blesession/blob/main/docs/bluetooth.ko.md)를 따르세요.

## 기기별 확인 사항

Defiant·Loyal·Honourable 지팡이와 Magic Caster Box를 충전하고 기기 안내에 따라 깨우세요. 연결을 점유하는 다른 BLE 앱을 종료하고 지팡이와 보관함을 각각 추가하세요. 이 통합에는 PIN·본딩 입력이 없으며 프로토콜 초기화는 기기 세션에서 처리합니다. 지속 연결은 슬롯을 사용합니다. 모든 실패 후 자동 재연결·재시도를 보장하지 않습니다. LED·진동 매크로를 다시 보내기 전에 실제 완료 여부를 확인하세요. 일부 실행된 명령을 반복하면 효과가 중복될 수 있습니다. 이번 적용에서 실물 지팡이·보관함, 펌웨어, 어댑터·프록시 조합을 새로 검증하지 않았습니다.

| 증상 | 실패 단계 | 확인 사항 | 조치 |
|---|---|---|---|
| 기기가 발견되지 않음 | 발견 | 충전·전원·깨우기 상태와 HA Bluetooth의 `MCW-*`·`MCB-*` 광고를 확인합니다. | 어댑터·프록시 가까이 옮기고 프록시 온라인 상태를 확인하세요. 수동 설정에는 HA가 이미 발견한 기기만 표시됩니다. |
| 발견되지만 Connect 실패 | 연결 | 광고 수신과 GATT 연결·프로토콜 초기화·쓰기는 별개입니다. | 연결 가능한 경로와 `bluetooth_proxy.active: true`, 여유 슬롯을 확인하고 다른 BLE 앱을 종료하세요. PIN·본딩 입력은 없습니다. |
| 연결 종료 또는 명령 무응답 | 전송 경로 끊김 | 배터리·실제 어댑터/프록시 경로·거리·프록시 전원·네트워크 단절을 확인합니다. | 기기를 깨우고 Connect를 다시 켜세요. 지속 연결은 슬롯을 사용하며 모든 실패 후 자동 재연결을 보장하지 않습니다. |
| 연결되지만 주문 없음 | 세션 / 주문 보고 | 지팡이의 Connect 상태와 평소 시전 조작을 확인합니다. | IMU·Canvas에는 Spell Tracking을 켜세요. TFLite 인식에는 접근 가능한 서버와 모델이 필요하며 모델은 여기서 배포하지 않습니다. |

| 보관함이 지팡이와 다름 | 기기 기능 | 보관함에는 뚜껑·USB·지팡이 유무와 단일 TIP LED만 있으며 진동 모터·IMU가 없습니다. | 두 기기를 각각 추가하세요. 보관함의 연결된 지팡이 주소는 사용자가 설정하는 HA 페어링 키가 아닙니다. |
| 진동 시간이 적용되지 않음 | 명령 완료 | 펌웨어는 명령 하나에 약 800 ms의 고정 펄스를 냅니다. | 연결 timeout과 구분하세요. 간격이 짧은 buzz 패킷은 진동을 연장할 수 있습니다. |
| LED·매크로 일부만 실행 | 전송 / 완료 | Last Failure와 기기의 실제 LED 상태를 확인합니다. | 쓰기 반환은 전체 효과 완료를 보장하지 않습니다. 매크로를 반복하면 효과가 중복될 수 있습니다. |

## 진단 및 로그

**설정 → 기기 및 서비스 → Magic Caster Wand → 기기**에서 진단 엔티티를 확인하세요. 비활성화된 엔티티는 엔티티 설정에서 활성화합니다. **개발자 도구 → 상태**에서 상태와 속성을 확인할 수 있습니다.

- **Connection Duration**: 최근 기록된 연결 작업의 시간과 속성입니다.
- **Failure Count**: 메모리에 기록한 실패 횟수이며 하드웨어 수명 전체의 누적 횟수가 아닙니다.
- **Last Failure**: 보관된 실패 시각과 보고 속성입니다. 이후 성공해도 지워지지 않으므로 시각을 비교하세요.
- **Connected**, **Connect**: 기기 연결 상태입니다. 실제 주문·LED 동작은 별도로 확인하세요.

보고에는 가능한 경우 `failed_stage`, `likely_cause_key`, `via_type`, `rssi`, `paths`, `via_unconfirmed`와 수치형 시간이 남습니다. `error`에는 예외 클래스만 포함됩니다. 원시 예외 메시지, 프록시·주소 식별자, `via`, `failed_detail`, 임의의 백엔드 메타데이터는 보관 전에 제거됩니다. 광고 수신과 신호 세기만으로 실제 연결 경로를 확정할 수 없습니다.

이 통합에서 `subscribe`·`notification`은 session 단계, `initialize`는 auth, `transfer`는 transfer로 대응됩니다. 따라서 auth 단계는 사용자가 입력한 비밀번호 오류가 아니라 프로토콜 초기화 실패일 수 있습니다. 단계·원인 키·예외 클래스·관찰된 동작을 함께 보고 조치를 선택하세요.

통합 로거 이름 공간은 `custom_components.magic_caster_wand`이며 기기 하위 모듈을 포함합니다. HA 통합 페이지에서 디버그 로깅을 켜고 한 번 재현한 뒤 끄세요. 자동화가 액션을 실행했다면 자동화 추적도 확인하세요. 전용 진단 다운로드 기능은 없으므로 실제 엔티티 보고와 해당 HA 로그를 사용합니다.

## 문제가 계속되는 경우

[기존 Issues](https://github.com/eigger/hass-magic-caster-wand/issues)의 제보 안내를 따라주세요.

가능하면 HA·통합·ESPHome·blesession 버전, 지팡이/보관함 모델과 펌웨어, 어댑터/프록시 모델·리비전·펌웨어, 로컬/원격 연결, 실패 시각·단계·오류, 재현 단계와 마지막 성공을 포함하세요. 실패 시도와 이후 성공 시도는 구분하고 다른 앱의 연결 여부와 명령 일부 실행 여부를 알려주세요.

공개 전에 엔티티 속성·추적·로그에서 MAC/Bluetooth 주소·기기 ID·일련번호·로컬 IP/호스트명·프록시 이름·위치·토큰·식별 정보를 제거하세요. 경로를 비교할 때는 일관된 대체 표기를 사용하세요.
